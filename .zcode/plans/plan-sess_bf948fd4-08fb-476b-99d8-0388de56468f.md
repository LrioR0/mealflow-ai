### LangGraph 迁移执行计划（按已确认边界：只改编排层，planning.py 等业务模块一行不动）

**改动文件仅 3 个**：`app/agent/state.py`、`app/agent/graph.py`、`app/services/agent_service.py`（仅 create_run 编排段）。

#### 1. state.py
`MealPlanningState` 保留既有键，新增承载对象的键：`context: PlanningContext`、`constraints: PlanningConstraints`、`kept: list`、`filtered_out: list`、`key_names: dict`、`chosen: list[RecipeContext]`、`requirements: dict`、`plan: AgentRunView | None`、`error: str | None`。

#### 2. graph.py（节点体 = 照搬 agent_service.py:185-328 的 `_plan` 顺序逻辑）
- 节点 `parse_request`：调 `_parse_constraints_with_llm`（含 LLM/降级，on_thinking 回调透传）→ 写 constraints + parse trace
- 节点 `load_context`：`load_planning_context` → 写 context；顺带产生 get_meal_service_context/list_inventory/get_member_constraints/search_recipe_candidates 四条真实 trace（与现行为一致）
- 节点 `build_options`：按原顺序调 `planning.build_key_names → hard_filter → score_candidates → build_all_options → choose_top(经 expiring_first 取 chosen) → compute_requirements → estimate_totals → procurement_lines`，每步真实计时写 tool_trace（含 on_step 直播回调）
- 节点 `wait_for_human`：`langgraph.types.interrupt(plan 摘要)` 挂起（先验证 v1.2 interrupt 可用；若与现有异步调用模型冲突则退化为直接返回 waiting 状态——不引入 checkpointer，不动任何其他模块）
- `build_meal_planning_graph()` 仍为模块级编译单例，`__init__` 导出不变

#### 3. agent_service.py（仅 create_run 接线）
253-313 行编排逻辑移入图节点；`create_run` 改为：构造初始 state → `graph.invoke(state, config)` → 终态取 traces/options/warnings/workspace_restrictions → 原 AgentRunView 构造与落库**原样保留**。`revise_run`、`get_run`、`_save_run`、`_parse_constraints_with_llm`、`_extract_constraints` 等全部不动（图节点直接复用）。

#### 4. 测试与验收
- 全量 pytest（37 个）必须全绿 —— 行为等价硬校验
- 新增 `tests/test_agent_graph.py`：同输入对拍（菜单项/成本/采购缺口与旧编排一致）+ 图可编译可运行
- 重启后端，curl create_run 链路验证响应结构与内容不变
