# 部署与运行手册(V2 家庭厨房版)

## 开发环境

目标环境:Python 3.12+、Node.js 20+、Docker Desktop(可选)。首次搭建与每日同步流程:

```text
# 后端(apps/api 下执行;DATABASE_URL 是相对路径,必须固定在该目录启动)
../../.venv/Scripts/python -m alembic upgrade head     # 拉取代码后必做:建表/升表
../../.venv/Scripts/python -m app.db.seed              # 首次/数据重置:灌家庭演示种子
../../.venv/Scripts/python -m uvicorn app.main:app --reload --port 8000

# 前端(apps/web 下)
npm ci
npm run dev          # http://localhost:5173,已配置 /api 代理到 8000
```

表结构变更由 Alembic 迁移管理,约定见 `apps/api/migrations/versions/README.md`;本地 `.sqlite3` 文件不进 git,演示数据可随时销毁:删除 `apps/api/data/local/mealflow.sqlite3` 后重新 `upgrade head` + `seed`。

> 注意:Windows 下 uvicorn `--reload` 偶发"日志显示 Reloading 但旧进程仍在服务",改完后端行为异常时直接重启进程并清理残留的 python 子进程。

## 演示数据(家庭厨房)

固定 ID 契约:`home-workspace` / `home-kitchen` / `home-lunch`(明日午餐 2 人);成员 `home-me`(感冒中:忌辛辣油腻)与 `home-partner`(例假期:忌辛辣生冷;忌口香菜;虾过敏)。菜谱 28 道(含辣子鸡/黄焖鸡米饭/豆角焖面),`taste_tags` 用于点名菜冲突检测;食材带 `reference_price`(市区大型超市公开参考价)。

## 配置

从 `.env.example` 复制为 `.env`,至少设置 `DATABASE_URL`、`LLM_PROVIDER`、`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、`CORS_ORIGINS`、`AGENT_MAX_STEPS`、`AGENT_TIMEOUT_SECONDS`。`.env` 永不提交,仓库与日志中不得出现模型密钥。默认智谱 GLM(`LLM_PROVIDER=zhipu`、`LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4`、`LLM_MODEL=glm-5.3-flash`);千问/DeepSeek 仅需换 `LLM_BASE_URL` 与 `LLM_MODEL` 两行。未配置模型或调用失败时自动降级规则基线:SSE 事件协议不变,仅无 thinking 事件、正文一次性输出。

## 登录(预留)

`/login` 路由与占位页已就位,`router.beforeEach` 守卫骨架已挂(当前直接放行)。后续版本实现账号登录时,替换占位页并打开守卫校验即可,不改动现有页面结构。

## 容器化与排障

`docker compose up --build` 提供 `api` 与 `web`;SQLite 通过命名卷持久化。启动失败按以下顺序排查:`docker compose ps`、`docker compose logs api`、数据库连接、模型密钥、Agent 超时、端口冲突和卷权限。生产迁移 PostgreSQL 前不得将 SQLite 用于多实例并发写入。SSE 接口(`POST /api/v1/agent/chat/stream`)经过反向代理时需关闭缓冲(`X-Accel-Buffering: no` 已内置)。
