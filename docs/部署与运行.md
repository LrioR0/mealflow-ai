# 部署与运行手册

## 开发环境

目标环境：Python 3.12+、Node.js 20+、Docker Desktop（可选）。Day 1 建立目录后，预期命令为：

```text
cd apps/api && pip install -r requirements.txt && uvicorn app.main:app --reload
cd apps/web && npm install && npm run dev
```

实际命令以提交的依赖文件为准；当前仓库尚未提供应用代码，不可执行上述命令。

## 配置

从 `.env.example` 复制为 `.env`，至少设置 `DATABASE_URL`、`LLM_PROVIDER`、`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、`CORS_ORIGINS`、`AGENT_MAX_STEPS`、`AGENT_TIMEOUT_SECONDS` 和 `KIOSK_TOKEN_SECRET`。`.env` 永不提交。V1 只调用云端 API：默认千问、DeepSeek 备用、智谱验证后可选；不安装模型、推理框架或 GPU 依赖。未配置模型或调用失败时必须启用规则基线。V2/V3 路线见 [模型选型与部署策略](模型选型与部署策略.md)。

公共 PC 自助终端以 `/kiosk` 路由进入浏览器全屏模式，可部署在普通 PC、触摸一体机或类似银行自助机的设备上。首次部署由管理员注册设备并获得设备令牌，浏览器只保存受限令牌；不得复用管理员令牌。设备重启后应恢复当前已发布餐次，不恢复上一位用餐者的评分、标签或备注。

## 容器化与排障

Day 3 时间充足时提供 `docker compose up --build`，服务至少包含 `api` 与 `web`；MVP 的 SQLite 通过命名卷持久化。启动失败按以下顺序排查：`docker compose ps`、`docker compose logs api`、数据库连接、模型密钥、Agent 超时、设备令牌、端口冲突和卷权限。生产迁移 PostgreSQL 前不得将 SQLite 用于多实例并发写入。
