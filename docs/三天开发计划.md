# MealFlow 国庆 MVP：三天双人开发计划

> 产品主线：企业食堂智慧运营助手。适用人员：Lrio、Colin。目标是完成管理员与员工的 B 端闭环，个人家庭版仅保留数据架构兼容性。

## 1. 范围冻结

必须交付：预置的示例企业食堂工作区、管理员/员工演示身份切换、站点与午餐餐次配置、预计用餐人数、饮食限制、库存录入与临期标记、20 道种子菜谱、批量菜单预览、硬约束过滤、临期优先排序、采购缺口汇总、菜单发布、员工查看菜单及评分/剩余反馈、推荐依据展示。

明确不做：注册登录、成员邀请、复杂 RBAC、多站点调拨、早餐/晚餐、供应商/支付、排班、RAG/MCP、图片识别、异步任务、真实商超数据、复杂营养计算和生产部署。`workspace(kind)`、`workspace_member` 与 `workspace_id` 从 Day 1 建立，但国庆版本只使用 `organization` 工作区。

## 4. 进度治理

- 每日 09:30 确认唯一可验收目标，20:30 演示运行结果；不以“代码写完”作为完成。
- Day 1 15:00 冻结数据模型与 API 名称，Day 2 12:00 冻结菜单预览结构；之后仅允许向后兼容改动。
- 风险优先级：工作区隔离与规则正确性 > 管理员/员工闭环 > UI 美化 > Agent > Docker。
- Day 2 中午闭环未通时，停止 Agent 与 Docker，集中修复“站点—人数—菜单—采购—发布—反馈”。
- 每个 PR 写明目的、验证步骤、风险和截图/API 响应，并由另一人审查。

## 5. Definition of Done

功能必须可从页面操作、经服务端校验、有自动化或可复现手工测试、错误对用户可理解，并同步更新接口或数据文档。
