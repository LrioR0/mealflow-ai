# 安全与隐私说明

MealFlow 管理端只收集实现运营所需的工作区、站点、餐次、饮食限制、库存和聚合反馈。餐厅公共 PC 自助终端不要求个人登录，不采集姓名、手机号或联系方式。饮食限制与过敏原属于敏感信息，仅用于硬过滤和推荐解释。

- LLM 密钥只存在于服务端 `.env`，禁止出现在浏览器、截图、日志、测试夹具和 Git 历史中。
- 后端必须校验数量、日期、单位、预计人数、评分、对象所属工作区、管理员角色和设备令牌；客户端校验不能替代服务端校验。
- 营养与替代建议统一标识为估算/一般烹饪建议，不能提供诊断、处方或过敏急救建议。
- Agent 默认只能调用只读和确定性计算工具；发布菜单必须经过管理员确认。评分终端不能访问管理端、库存或 Agent 接口。
- 原始文字备注先限长、脱敏并按不可信输入处理；仅将聚合标签和安全摘要交给 Agent，防止提示注入。
- Kiosk 提交、刷新、崩溃恢复或餐次切换后必须清除上一位用餐者的评分、标签和备注；以设备频率限制、冷却时间和异常检测减轻刷票，不宣称严格一人一票。
- V1 只调用千问/DeepSeek/智谱等云端 API，并且只能使用演示种子数据；真实政务数据是否可发送到外部模型必须经过客户审批。V2 继续做云端工程化，V3 才按项目条件评估内网或专有云模型服务。
- 发现密钥泄露时立即吊销密钥、清理部署环境、用新密钥替换，并通过提交历史删除或轮换暴露的凭据。
