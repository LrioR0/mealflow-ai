# 餐厅公共 PC 自助评分终端设计

## 1. 产品形态

终端本质是一台运行 Windows 或 Linux 的 PC，可连接触摸屏并安装在类似银行自助机的一体化机身中。软件不需要开发桌面客户端，直接由浏览器以全屏 Kiosk 模式打开 `/kiosk` Web 页面。它与管理员端共用 Vue 工程和 FastAPI 后端，但使用独立布局、路由守卫和受限设备令牌。

终端放置在食堂出口。用餐人员无需登录、无需手机扫码，不采集姓名、手机号或联系方式。匿名模式无法证明严格一人一次，因此 V1 只做合理防刷和异常标记，不作“一人一票”承诺。

## 2. 页面流程

```text
读取当前已发布餐次
  → 显示当餐菜单、热量和过敏原提示
  → 选择总体评分（很好/满意/一般/不满意）
  → 可选快捷标签（太咸/太辣/份量少/温度低/很喜欢）
  → 可选展开文字备注
  → 提交反馈
  → 感谢页 2–3 秒
  → 清空内存、表单和临时状态
  → 返回初始页面供下一位使用
```

评分按钮需适合触摸操作；文字备注默认折叠，避免屏幕键盘阻塞队列。页面不显示后台导航、历史反馈或上一位输入。退出全屏模式和更换绑定站点属于维护操作，可在后续加入管理员 PIN。

## 3. 设备身份与接口

设备注册后获得一次性明文令牌，服务端仅保存哈希。浏览器使用令牌调用：

- `GET /api/v1/kiosk/current-menu`：读取绑定站点当前已发布菜单。
- `POST /api/v1/kiosk/feedback`：提交评分、标签、可选备注和剩余等级。

设备令牌不能调用库存、Agent、管理端和发布接口。反馈记录保存 `workspace_id`、`site_id`、`meal_service_id`、`meal_plan_id`、`device_id`、`rating`、`tags`、`comment`、`leftover_level` 与时间；不保存 `user_id`。

## 4. 防刷与隐私

- 提交成功后设置短暂冷却，接口按设备限流。
- 对短时间重复内容和异常峰值标记，管理端可在统计时排除可疑批次。
- 备注限长、脱敏并作为不可信输入；不记录键盘输入过程。
- 原始备注不直接拼接进 Agent 提示词，只提供规则标签与安全摘要。
- 终端刷新、崩溃恢复和餐次切换时必须清空未提交表单。

## 5. Agent 如何使用反馈

Agent 读取按餐次和菜品聚合的平均分、标签占比、备注安全摘要、样本量和剩余等级。反馈只影响满意度等软评分，不得突破过敏原、禁用食材和食品安全规则。低样本或异常批次只能作为提示，不自动禁用菜品。

V1 演示需连续提交两次不同反馈，证明终端自动重置；随后在下一次规划中展示类似“上次评分偏低且‘太咸’标签较多，因此降低原方案权重并提示调整调味”的可解释变化。
