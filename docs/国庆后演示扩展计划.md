# MealFlow V1 之后的迭代路线

> V1 已定义为国庆期间 3–4 天开发、国庆后演示的版本。本文件不再增加 V1 范围，只记录演示完成后的迭代方向。

## 第一阶段：试点加固

- 真实管理员会话、角色权限、操作审计和密码策略。
- PostgreSQL、Alembic 迁移、备份恢复和部署监控。
- 多餐次、多站点、预计/实际人数与库存盘点。
- 公共 PC 终端注册、维护 PIN、离线提示、设备健康和异常反馈检测。
- 30–50 条 Agent 固定评测集、回归看板和提示词/工具版本管理。
- 菜谱 SOP RAG，但仍以结构化配方和规则计算为事实来源。
- V2 继续使用千问、DeepSeek 或智谱云端 API，完善 Provider 评测、自动故障转移和成本统计，不部署本地模型。

## 第二阶段：V3 政务部署与私有化验证

- 仅在客户要求数据不出域且具备算力和运维条件时，开展候选国产模型的私有化部署与业务评测。
- 对接统一身份、日志审计、采购或机关事务系统前先确认接口和数据边界。
- 完成安全测评、最小权限、数据脱敏、密钥管理和故障演练。
- 将 SQLite 和演示账号替换为正式基础设施，不复用 V1 演示凭据。

## 第三阶段：智能运营

- 用餐人数预测、剩余与浪费风险预测、采购量建议。
- 跨餐次/站点分析和定时生成菜单草案。
- 在单 Agent 的稳定性、可观测性和评测达标后，再评估是否需要多个专业 Agent。

个人家庭版仍只保留架构兼容，不占用 B2G 主线开发容量。
