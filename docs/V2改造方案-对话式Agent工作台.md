# MealFlow V2 改造定稿:智能配餐 Agent(家庭厨房主线 × 政务食堂第二场景)

> 定稿日期:2026-10-06(v2.2,场景重构:新增家庭厨房主线与约束前置模型;v2.1 并入流式对话;初稿 2026-10-05)。依据:Codex 咨询 + 团队确认。
> 定位:基于 V1 成果的**体验与场景重构**,不是推倒重写。确定性工具内核、库存、菜谱、成本、评分、发布、反馈全部复用。

> **⚠ 场景决策(2026-10-06 已执行):** 家庭厨房场景为**唯一主线**,政务食堂相关文档(13 篇)与代码(kiosk/feedback/评分终端等)已全部删除,`kiosk_devices`/`feedback` 表已 drop。确定性工具内核、库存、菜谱、成本、评分、发布链路保留并复用。前端引入 Element Plus,侧栏可折叠,`/login` 已留路由与守卫口子。

## 1. Agent 要解决的问题(产品定义)

> 家里有我和我对象两个人,冰箱里有食材;我们各有忌口,还会发生"她来例假了""我感冒了"这类**特殊事件**。做饭前我们会说想吃什么、预算多少;Agent 在**约束优先**的前提下给方案——点名想吃的菜照常给菜单和食谱,但与约束冲突时会明确提示"不建议做",并给出替代。

拆成五条产品规则:

1. **约束前置**:成员档案(每人忌口/过敏)+ 特殊事件(例假/感冒等,带生效日期)先于一切问答注入,Agent 每轮先"检查用餐限制";
2. **库存优先**:冰箱食材是第一输入(拍照/手填,家庭单位:个/克/盒),方案最大化消耗现有食材;
3. **点名菜不硬拒**:想吃辣子鸡 → 照常出菜单 + 完整食谱(2 人份用量与步骤),但若与忌口/事件冲突,给出**不建议**警示 + 冲突原因(引用具体成员与事件)+ 替代建议;
4. **物价可溯源**:成本与采购建议按**市区大型超市参考价**计算,所有金额处标注来源("价格参考:市区大型超市公开参考价,2026-10"),不做不可信的实时报价;
5. **预算软约束**:预算是权衡项,超支要讲清差多少、差在哪个食材,而不是静默截断。

## 2. 现状诊断(V1 → V2 差距)

| # | 现状问题 | V2 改造后 |
|---|---|---|
| 1 | 展示研发内部过程(约束卡/10 节点轨迹/评分权重)先于结果 | 先给结果,过程收进可折叠"决策过程" |
| 2 | 三方案只是权重排序,差异弱 | 1 主推荐 + 2 备选,主推荐可发布,每卡附完整菜单 |
| 3 | 只能提取 N人/预算N元/清淡/花生/临期 5 个关键词 | 理解点名菜品、忌口、特殊事件、预算,主动补问 |
| 4 | 约束只有静态过敏原,没有"人的维度"(成员、临时健康事件) | 成员档案 + 特殊事件(带生效期)成为一等输入,自动过期 |
| 5 | 点名菜会被硬过滤或无视,没有"照常出但提示不建议"的能力 | 冲突检测:警示 + 原因 + 替代 chips |
| 6 | 成本无来源标注,可信度弱 | 金额全部挂"市区大型超市参考价"来源标签 |
| 7 | 无菜品食谱详情(做法/用量点不开) | 方案卡展开即食谱:用量换算 + 步骤 + 热量 |
| 8 | 提交后黑盒等待 | 全程流式:思考小字 → 步骤打勾 → 逐字回答 → 方案卡 → 反问 |
| 9 | 界面是后台观感 | 对话驱动三栏工作台 |

## 3. 改造原则:三不变、三转变

**不变:** ① 确定性工具内核(库存占用、换算、热量/成本、缺口、评分、降级);② 人工确认才产生副作用 + 反馈闭环;③ 模型失败降级规则基线,HTTP 契约稳定。

**转变:** ① 场景:单一政务食堂 → 家庭主线 + 政务第二模板;② 交互:表单后台 → 对话工作台 + 全程流式;③ 约束:静态过滤 → "人 + 时间"动态约束前置。

## 4. 目标信息架构:三栏工作台 + 家庭档案

```
┌──────────────┬────────────────────────────┬──────────────┐
│ 对话区(左侧) │  方案区(中间,主舞台)      │ 决策依据(右侧)│
│              │                            │              │
│ 消息流(流式):│  ★ 主推荐(可发布)          │ · 本餐成本    │
│  用户气泡    │   菜品卡:点击展开食谱      │ · 人均热量    │
│  Agent气泡:  │   (用量/步骤/热量)         │ · 冰箱消耗    │
│   思考小字(折叠)│ 备选一/二(可切换)       │ · 采购缺口    │
│   工具步骤✓  │  [确认:就做这套]           │ · 预算余量    │
│   逐字回答   │  冲突菜卡带"不建议"警示条   │ · 价格来源标注 │
│   方案卡摘要 │                            │              │
│   反问chips  │                            │              │
│ 输入框       │                            │              │
├──────────────┴────────────────────────────┴──────────────┤
│ 家庭档案条(顶部常驻):成员卡[我·感冒中(忌辛辣油腻)]      │
│ [对象·例假期(忌辛辣生冷)] [+记一笔事件] [☰ 冰箱 12 种]    │
└──────────────────────────────────────────────────────────┘
```

- **家庭档案条**:常驻顶栏。成员卡片显示永久忌口 + 当前生效的特殊事件徽标(按日期自动出现/过期);`+记一笔事件` 两步完成(选成员 → 选事件类型与日期,忌口 tags 自动带出可改);`冰箱` 打开库存抽屉(复用现有 InventoryView,家庭单位)。
- **对话区/方案区/依据区**:同 v2.1;方案区菜品卡新增**食谱展开**(食材用量按 2 人换算、步骤、热量、成本);冲突菜卡顶部显示警示条(黄 = 不建议,红 = 禁忌如过敏原)。
- **旧页面去向**:同 v2.1(政务 Inventory/Procurement/Dashboard 路由保留、导航隐藏;Kiosk 独立入口保留,归入政务模板)。

## 5. 消息生命周期与流式交互(v2.1 全文保留)

| 阶段 | 界面表现 | 数据来源 |
|---|---|---|
| ① 思考中 | 气泡顶部小字流动区,思维链增量滚动 + 转圈图标 | 模型 `reasoning_content` |
| ② 工具执行 | 逐条打勾:`✓ 理解需求` `✓ 检查用餐限制(引用成员与事件)` `✓ 匹配冰箱与菜谱` `✓ 按超市价算成本` | **真实工具轨迹**直播 |
| ③ 回答流式 | 思考区折叠,正文逐字输出(Markdown 实时渲染) | 模型 `content` 增量 |
| ④ 方案卡 | 主推荐 + 2 备选,每卡必附菜单;冲突菜带警示条;点击展开食谱 | `plan` 事件 |
| ⑤ 反问 | 可点击 chips(替换建议/确认),点击即发送 | `questions` 事件 |

完成后思考区折叠为"✦ 已深度思考 · 用时 Xs"可回看;工具步骤保留;方案卡与 chips 常驻。

## 6. 黄金样例(P0 验收用例)

**样例 A · 点名菜 + 特殊事件冲突(核心新能力):**
> 输入:"明天中午想吃辣子鸡,我们俩,预算 60 块。"
>
> Agent(思考流 → 步骤打勾 → 逐字回答):
> "辣子鸡可以给你出菜单和食谱,但**不建议现在做**:你的对象在例假期(10-06 至 10-07,忌辛辣生冷),你正感冒(10-06 至 10-08,忌辛辣油腻)——这道菜和两条限制都冲突。
>
> [方案卡:辣子鸡(2人份,⚠ 不建议)]
> 　食谱:鸡肉 300g、干辣椒 20g、花椒 5g、花生米 30g…
> 　步骤:①鸡丁码味 ②煸干水汽 ③炝锅下辣椒…
> 　预计成本 32.5 元(价格来源:市区大型超市参考价,2026-10)
>
> 更推荐这些不辣的:[黄焖鸡米饭] [番茄炒蛋 + 清炒时蔬],要我换吗?"
> chips:`仍要做辣子鸡` `换成黄焖鸡` `看看其他不辣方案`

**样例 B · 约束前置 + 库存优先(从 v2.1 改写为 2 人语境):**
> 输入:"明天中午我俩想吃豆角焖面,冰箱有什么用什么,预算 60。"
> Agent:"已保留豆角焖面。你的对象忌口香菜,已避开;冰箱的挂面 500g、豆角 300g 优先用掉,还需采购豆角 300g、五花肉 150g,约 18.4 元(市区大型超市参考价)。预算还剩 41.6 元。"+ 两备选卡 + chips。

**样例 C · 主动补问:**
> 输入:"晚上吃点清淡的。"
> Agent:"好,清淡为主。你对象今晚在家吗(决定 1 人还是 2 人份)?冰箱里的番茄和鸡蛋要不要消耗掉?" + chips:`就我自己` `两个人都在` `优先消耗番茄鸡蛋`。

验收线:样例 A 的"照常出 + 警示 + 替代"、B 的"约束前置 + 库存优先 + 价格来源"、C 的"主动补问"、再加全程流式——四条全过才算改造完成。

## 7. 功能范围

**P0:**
1. **家庭档案**:成员 CRUD(姓名/永久忌口/过敏);特殊事件 CRUD(成员、类型:例假/感冒/肠胃不适/康复期/其他、日期范围、自动带出忌口 tags 可改、到期自动失效);
2. **家庭种子工作区**:2 成员(我:感冒中;对象:例假期 + 忌香菜)、冰箱 12 种食材(家庭单位)、菜谱库含 辣子鸡/黄焖鸡/豆角焖面 及口味 tags(辛辣/油腻/生冷/清淡…);
3. **约束前置注入**:每轮对话上下文自动携带"永久忌口 + 当日生效事件",工具步骤明示检查结果;
4. **点名菜冲突检测**:菜口味 tags × 生效约束 → 警示(黄=不建议,红=过敏禁忌)仍出菜单与食谱,附原因与替代 chips;
5. **食谱详情**:方案卡点击展开(用量按人数换算、步骤、热量、成本);
6. **价格来源标注**:ingredients 增加 `reference_price` + `price_source`(默认"市区大型超市公开参考价")+ `price_updated_at`;所有金额与采购行挂来源;
7. 多轮会话 + **SSE 全程流式**(§5 五阶段)、意图路由(create/modify/clarify/confirm)、对话式修改、确认生成采购清单;
8. 无模型降级:同一 SSE 协议,无思考事件、步骤照常直播、正文一次给出。

**P1:** 冰箱拍照识别、菜谱扩至 40+、事件日历视图、采购清单分享、政务模板适配(会议餐/值班餐映射特殊事件)。

**本期不做:** 登录权限、语音、移动端、实时比价爬虫(只做参考价标注)。

## 8. 技术方案

### 8.1 流式协议(SSE,v2.1 协议 + 2 处扩展)

端点与解析方式不变:`POST /api/v1/agent/chat/stream`,`fetch + ReadableStream` 解析(不用 EventSource)。

```
event: thinking   data: {"delta": "…"}                                    # 思维链增量
event: status     data: {"step":"检查用餐限制","state":"done",
                         "detail":"对象·例假期(忌辛辣生冷);我·感冒(忌辛辣油腻)"}  # ← 引用具体成员/事件
event: text       data: {"delta": "…"}
event: plan       data: { ...PlanView, options:[{items:[菜单], warnings:[{
                          "level":"warn|forbidden",                        # ← 新增:冲突警示
                          "reason":"与 对象·例假期(忌辛辣) 冲突"}]}] }
event: questions  data: {"items":["换成黄焖鸡","仍要做辣子鸡"]}
event: done/error data: {...}
```

契约红线:`plan.options[*].items` 为空即违规(菜单必附);警示必须引用具体成员与事件;`status.detail` 不得出现内部字段名。

### 8.2 后端

**数据模型**(一个迁移):
- 新表 `member_events`:id、member_id(FK users)、event_type、constraint_tags(JSON)、start_date、end_date、note;
- `ingredients` 加列:`reference_price` Numeric、`price_source` String(默认"市区大型超市公开参考价")、`price_updated_at`;
- `recipes` 加列:`taste_tags` JSON(如 ["辛辣","油腻"]),种子菜谱补 tags 与做法步骤(已有则校验);
- v2.1 的 `agent_chat_sessions` / `agent_chat_messages`(含 thinking_text、run_id、plan_id)不变。

**新接口:**
```
POST/GET/DELETE /api/v1/household/members/{id}/events      # 特殊事件 CRUD
PATCH           /api/v1/household/members/{id}             # 永久忌口维护
GET             /api/v1/recipes/{id}                       # 食谱详情(用量按人数换算+步骤)
POST /api/v1/agent/chat[/stream]、GET /agent/chat/{id}     # v2.1 不变
```

**编排逻辑**(`chat_service.py`,复用现有模块):
1. 约束前置:`load_planning_context` 扩展——注入永久忌口 + 当日生效事件及其 tags(替代 v1 仅工作区预置限制);`status` 事件输出检查结果;
2. 点名菜:命中菜谱库 → 强制入选;其 `taste_tags` × 生效约束 → `warnings`(level/reason 引用成员+事件)+ 生成替代建议(同 `swap_dish` 的确定性推荐);若命中**过敏原**→ `forbidden` 级,默认不出、需用户点击"我知道风险,仍要做"确认;
3. 预算权衡:成本估算统一走 `reference_price`,所有金额输出携带 `price_source`;超预算在正文与依据区明示差额;
4. 意图路由(create/modify/clarify/confirm)与降级链同 v2.1;失败走规则关键词,规则版同样执行约束检查与警示(确定性逻辑,不依赖模型)。

### 8.3 前端

- `ConversationWorkbench.vue` 三栏 + 顶部**家庭档案条**;组件:`MemberStrip` / `EventDialog`(两步记事件)/ `ThinkingLine` / `ToolSteps` / `TypewriterMarkdown` / `PlanCards`(警示条 + 食谱展开)/ `QuestionChips` / `EvidencePanel`(含价格来源脚注)/ `TraceDrawer` / `FridgeDrawer`(复用 InventoryView);
- `sseClient.ts`(fetch 流解析)不变;警示条分黄/红两级样式;过敏禁忌确认需点击穿透;
- 导航:`智能配餐` 主入口;`评分终端`、库存/采购收进抽屉(政务模板演示时从"场景切换"进入)。

## 12. 验收 DoD 与风险止损

**DoD:** 样例 A/B/C 全过且全程流式;警示必须引用成员与事件;过敏原为 forbidden 级需确认;事件到期自动失效;所有金额带价格来源;plan 必含菜单;重启可恢复会话;发布幂等;断网/模型超时降级可演示;单测覆盖事件过期、冲突分级、事件顺序、发布幂等;仓库与日志无模型密钥。

**风险与止损:**
- SSE 被代理缓冲 → 响应头 `X-Accel-Buffering: no` 已内置,D1 上午真流验证;不通回退"轮询 + 本地打字机";
