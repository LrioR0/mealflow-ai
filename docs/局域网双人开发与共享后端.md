# 局域网双人开发与共享后端

## 目标架构

两台电脑都保留完整项目代码，各自开发和运行前端；同一时间只启动一台共享后端。

```text
你的电脑                         对方电脑
├─ 前端 localhost:5173            ├─ 前端 localhost:5173
└─ 后端 0.0.0.0:8000  ◄───────────┘
       │
       └─ 你的 data/local/mealflow.sqlite3
```

两台电脑的前端都通过环境变量把 `/api` 代理到当前后端主机，因此人员、库存、采购清单、下厨足迹和 Agent 会话使用同一份数据。

## 一、代码怎么同步

两个人各自克隆或复制项目代码，不要复制运行时数据和密钥：

### 可以同步

```text
apps/api/app/
apps/api/migrations/
apps/web/src/
apps/web/package.json
apps/web/package-lock.json
apps/web/vite.config.ts
```

推荐使用 Git 分支和提交同步代码。

### 不要复制

```text
.env                         # 含 LLM API Key 等私密配置
data/local/                  # 只保留当前后端主机的数据库
apps/api/data/local/         # 迁移命令误生成的本地副本，不作为共享数据
apps/web/node_modules/
apps/web/dist/
.venv/
```

## 二、当前谁作为后端主机

先在后端主机电脑查看无线网 IP：

```powershell
Get-NetIPAddress -AddressFamily IPv4
```

找到 `WLAN` 网卡的 IPv4，例如：

```text
192.168.1.27
```

### 后端主机启动

在项目根目录执行：

```powershell
cd D:\Agent\mealflow-ai
$env:PYTHONPATH="$PWD\apps\api"
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

后端必须使用 `--host 0.0.0.0`，否则只能本机访问。

## 三、两台电脑各自启动前端

### 后端主机自己的前端

创建 `apps/web/.env.local`：

```env
VITE_API_PROXY_TARGET=http://127.0.0.1:8000
```

启动：

```powershell
cd D:\Agent\mealflow-ai\apps\web
npm install
npm run dev -- --host 0.0.0.0
```

本机打开：

```text
http://localhost:5173
```

### 另一台开发电脑的前端

在另一台电脑自己的项目目录中创建 `apps/web/.env.local`：

```env
VITE_API_PROXY_TARGET=http://192.168.1.27:8000
```

把 `192.168.1.27` 替换成当前后端主机的 WLAN IP。

然后启动自己的前端：

```powershell
cd 项目目录\apps\web
npm install
npm run dev -- --host 0.0.0.0
```

她打开自己的：

```text
http://localhost:5173
```

她的浏览器访问的是自己的前端，但 API 请求会由她本机 Vite 转发到你的后端。

## 四、互换后端主机

如果以后改成对方电脑作为后端主机：

1. 对方电脑启动后端：

```powershell
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

2. 你电脑的 `apps/web/.env.local` 改为：

```env
VITE_API_PROXY_TARGET=http://对方电脑WLAN-IP:8000
```

3. 重启你自己的 Vite 前端。

4. 对方自己的前端仍然使用：

```env
VITE_API_PROXY_TARGET=http://127.0.0.1:8000
```

## 五、Windows 防火墙

后端主机需要允许 8000 端口：

```powershell
New-NetFirewallRule `
  -DisplayName "MealFlow LAN API" `
  -Direction Inbound `
  -Protocol TCP `
  -LocalPort 8000 `
  -Action Allow
```

如果另一台电脑需要访问后端主机上运行的前端，也允许 5173：

```powershell
New-NetFirewallRule `
  -DisplayName "MealFlow LAN Web" `
  -Direction Inbound `
  -Protocol TCP `
  -LocalPort 5173 `
  -Action Allow
```

## 六、数据库和种子数据规则

共享数据库只存在于当前后端主机：

```text
data/local/mealflow.sqlite3
```

不要在另一台开发电脑复制或启动自己的数据库来参与共享，否则会产生两份数据。

当前种子脚本已经改为：

- 已有家庭不重新覆盖成员资料；
- 已有库存不重新覆盖数量、单位和到期日；
- 种子只用于空数据库的初始化。

## 七、共享数据范围

已经接入后端共享：

- 人员信息；
- 过敏、忌口和特殊事件；
- 冰箱库存；
- Agent 会话；
- 采购清单；
- 下厨足迹文字记录。

暂时不共享：

- 下厨足迹图片仍保留在浏览器本地；
- 消息中心已读状态仍保留在浏览器本地；
- 各自浏览器的页面滚动位置和 UI 状态。

## 八、启动检查

后端主机检查：

```text
http://后端主机IP:8000/docs
```

另一台电脑检查：

```powershell
ping 后端主机IP
```

然后检查：

```text
http://后端主机IP:8000/openapi.json
```

如果能看到以下路径，说明共享后端已经是最新版本：

```text
/api/v1/household/members
/api/v1/workspaces/{workspace_id}/procurement-items
/api/v1/workspaces/{workspace_id}/cooking-records
```
