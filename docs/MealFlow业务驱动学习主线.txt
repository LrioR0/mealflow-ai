MealFlow 业务驱动学习主线
============================

目标
----
不是从头补完所有课程，而是借 MealFlow 这个真实项目，学会：

1. 看懂一项功能从前端到后端再到数据库/模型的完整路径；
2. 判断 AI 生成的代码该放在哪里、是否安全、是否真的解决问题；
3. 独立完成小改动，并用测试证明它没有弄坏原有功能。

本学习主线只使用课程目录中的文字笔记、代码和课件；不学习视频文件。


先记住一条主链路
------------------

用户发消息
  -> Vue 前端请求
  -> FastAPI 路由
  -> Pydantic 校验
  -> 业务服务 / 数据库
  -> LLM Function Calling
  -> Agent 工具循环
  -> SSE 流式结果回前端

每学习一个主题，都要回到这条链路中回答：输入是什么？输出是什么？谁负责校验？

阶段 4：重点——Function Calling 和 Agent
----------------------------------------

课程资料：

- D:\千锋大模型课程\day30Agent\笔记\智能体开发.md
  重点：状态、结构化输出、流式处理；
- D:\千锋大模型课程\day35langgraph\day35LangGraph\笔记\LangGraph.md
  重点：状态机与条件分支概念。

项目代码：

- apps/api/app/agent/intent.py
- apps/api/app/services/menu_composer.py

要掌握：

- 工具调用必须有限制、可追踪、可测试。

练习：
先画出“用户需求 -> 意图解析 -> 工具调用 -> 菜单编排 -> 回答”的流程图；
再尝试设计一个只读工具 get_expiring_inventory，先说清楚输入、输出和测试，再开始写代码。

阶段 6：MCP、RAG、LangGraph 放到最后
------------------------------------

课程资料：
- D:\千锋大模型课程\day31Agent和MCP\笔记\MCP.md
- D:\千锋大模型课程\day26LangChain入门和RAG\笔记\RAG.md
- day35 LangGraph 笔记。

当前只理解概念，不急着接入 MealFlow：
- MCP：让多个 Agent 或外部客户端复用工具；
- RAG：检索大量非结构化文档，不替代业务数据库；
- LangGraph：流程很复杂、状态和分支很多时使用。

MealFlow 当前的菜谱、库存和限制是结构化业务数据，优先学透现有的 Function Calling + 后端服务架构。


每天的固定学习闭环（45 到 90 分钟）
-----------------------------------

1. 只读一个很小的课程主题；
2. 找到 MealFlow 中对应的 1 到 3 个文件；
3. 写下：输入、输出、依赖、校验、失败时怎么办；
4. 完成一个极小改动或测试；
5. 运行相关 pytest；
6. 查看 git diff；
7. 把“我的理解”和“卡住的位置”发给 Codex，请求代码审查，而不是直接索要完整答案。


暂不学习的内容
--------------

- 深度学习训练、CNN、PyTorch；
- 机器学习算法和数学推导；
- 为了“看起来 AI”而强行接入 RAG、MCP、LangChain 或多 Agent；
- 大型重构和一次改很多文件。

先把一条真实业务链路走通并能自己修改，学习会变得非常快。
